# AMAZON-AUTO

中文 Excel 工作台：上传多工作表补货文件，分别计算 FBA 发货需求和供应商采购缺口，导出可核对的 Excel。第一版围绕用户提供的原工作簿表头开发；不连接亚马逊、不自动采购、不创建货件。

## 运行

需要 Python 3.12；依赖仅 openpyxl。使用当前隔离环境中的现有仓库，不需要另建 Git worktree。

```bash
cd /workspace/AMAZON-AUTO
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python server.py --host 127.0.0.1 --port 8000
```

这是单用户开发服务，默认只监听本机，不提供账号认证；公网部署需另行配置认证、HTTPS、访问隔离和请求资源限制。云环境中的服务通过本地 HTTP 请求验证，不将 loopback URL 作为用户预览链接。

## 使用

1. 上传 `.xlsx`（20 MB 以内）。工作表名允许日期后缀变化。同一类存在两个日期版本时拒绝计算，先保留目标版本。
2. 选择店铺、数据日期、销量口径与周期。用户确认生产45天、运输及上架50天。默认沿用原表销量梯度：日销>49覆盖100天，>19覆盖90天，其余80天，也可手动指定。安全库存7天是可编辑假设。
3. 厂家已出/未出是袋子数据，不参与计算；计划单已完成是当前国内未发货现货。确认本次各表为同日快照及当前结余后启用正式建议，未知计划状态仍会阻止对应商品建议。
4. 查看待办和数据错误，搜索商品，导出六张结果表。参数改变或换文件会使旧结果失效。

**必需工作表**：`货件补货计算…`（FNSKU、产品名称、单箱数量、可选预期日销）；`FBA库存明细…`；`listing报告…`。源表使用原文件的中文表头。**可选**：`计划单…`、`厂家已出…`、`厂家未出…`、`已创数据…`、`ADW库存`/`AWD库存`。当前不支持任意后台格式或多个文件合并。核算范围是主表有 FNSKU 的商品，非所有 listing。

上传内容只在进程内存中处理，不写入磁盘。仓库不包含用户上传文件或真实业务数据。服务端返回导出文件给浏览器下载，不自动留存上传历史。

## 计算规则与限制

详见 [业务规则](docs/business-rules.md)。所有数量按销售单位计算，整箱向上补齐；建议国内发货受当前国内现货整箱数限制。销量为0时人工复核；空白销量、缺库存、重复商品、非法数字会阻止计算，不能自动当作0。

API：`GET /health`；`POST /api/inspect` 和 `POST /api/calculate` 接收 JSON `{ "file": "工作簿的base64", "options": {...} }`。计算返回明细、待办、口径，以及 base64 编码的导出工作簿。

当前“已创数据”只做装箱核对。原表缺少逐行关联的货件编号和实际接收数量，无法计算亚马逊短收。后续接入需以“货件编号 + FNSKU”为粒度，区分接收中与已关闭，避免将尚未接收的数量误报为丢失。

## 验证

`python3 -m unittest discover -s tests -v` 验证独立发货/采购计算、整箱、现货限制、发货扣减、订单去重口径、跨店铺、零/空销量、重复与缺失记录、异常工作表维度、装箱核对、Excel 导出。测试使用人工构造数据，不包含真实用户文件。
